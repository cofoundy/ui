## Repro (verified, not inferred)

`src/components/chat-sim/react/MessageThread.tsx:168-170`:

```ts
const reactionsEl = msg.reactions.length > 0 ? <Reactions reactions={msg.reactions} style={adapter.reactions} /> : null;
const reactionsInsideBubble = reactionsEl && adapter.reactions !== 'own-row';
const reactionsOwnRow = reactionsEl && adapter.reactions === 'own-row';
```

`a && b` evaluates to `b` (not `a`) when `a` is truthy — so both `reactionsInsideBubble` and
`reactionsOwnRow` are plain **booleans**, never the `reactionsEl` JSX element itself. React
renders `{true}`/`{false}` as nothing, so `{reactionsInsideBubble}` / `{reactionsOwnRow}` at
lines 184/187 never render the reaction pill — for **any** channel, since both branches share
the same bug (one flips true, the other false, but neither is ever the element).

Minimal repro, run directly (no React needed to see the defect):

```js
const reactionsEl = { fake: 'jsx-element' }; // any truthy value stands in for the real element
for (const style of ['own-row', 'overlay-below']) {
  console.log(style, reactionsEl && style !== 'own-row', reactionsEl && style === 'own-row');
}
// own-row       -> false true   (both booleans)
// overlay-below -> true  false  (both booleans)
```

Confirmed against the real component: rendering `<ChatSim>` (via the public barrel,
`react/index.ts`) with a script that posts a message and reacts to it —

```ts
const script: SimScript = [
  { k: 'post', by: 'in', text: 'reservado!' },
  { k: 'react', id: 'm0', emoji: '❤', by: 'out:ai' },
];
render(<ChatSim script={script} channel="whatsapp" seed={1} mode="live" />);
```

— produces a `finalState.msgs.get('m0').reactions` array that DOES contain the reaction
(verified directly via `compile()` + `core/seek.ts`'s `stateAtStep`, and again by rendering
`<MessageThread>` directly with hand-built props from that same state), yet the rendered DOM has
no `.cf-reactions` node anywhere. Reproduced identically on Telegram (`own-row` style) and
WhatsApp (`overlay-below` style) — i.e. it's channel-independent, exactly as the buggy boolean
logic predicts.

## Por qué [app]'s own tests are green today

`react/__tests__/ChatSim.test.tsx` and `react/__tests__/snapshot-cross-check.test.tsx` never post
a script step with a `react` event — none of the existing fixtures exercise a message that has
any reactions at all, so `msg.reactions.length > 0` is always `false` in every prior test, and
the buggy `&&` chain's output (a boolean instead of the element) never mattered because the
element was `null` either way.

## Acceptance (falsable)

1. A message with ≥1 reaction, rendered via `<ChatSim>` on WhatsApp (`overlay-below`), produces a
   `.cf-reactions[data-style="overlay-below"]` node containing the reaction emoji, nested inside
   `.cf-bubble`.
2. The same on Telegram (`own-row`) produces `.cf-reactions[data-style="own-row"]` as a sibling of
   `.cf-bubble` (inside the `<li>`, not nested in the bubble span) — matching
   `element/render.ts`'s own overlay-vs-own-row placement, since T-007 acceptance #1's cross-DOM
   snapshot check depends on the two trees matching.
   **Gemelo negativo:** a message with zero reactions must render neither node (this already
   works today — the bug only ever suppressed the truthy case).
3. `src/__tests__/chat-sim/chatsim-cross-channel-states.test.tsx` ([qa]'s test, out of `app`'s
   write cell — do not edit it to make it pass; fixing `MessageThread.tsx` is what should make it
   pass) goes green once this lands.
